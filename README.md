# Taskly Bot — Fresh Project v2

این نسخه برای یک پروژه جدید ساخته شده و عمداً از دیتابیس پروژه قبلی استفاده نمی‌کند. دیتابیس پیش‌فرض `taskly.sqlite3` است.

## امکانات اصلی
- 6 شبکه: YouTube, Instagram, TikTok, Telegram, Facebook, X
- فارسی / English / हिन्दी
- My Channels با افزودن، ویرایش لینک و حذف
- تایید/رد کانال توسط مدیر
- خرید سابسکرایبر بر اساس شبکه و قیمت مستقل هر شبکه
- مدیر می‌تواند قیمت هر شبکه را مثلاً 0.01 / 0.02 / 0.05 تغییر دهد
- پرداخت سفارش با USDT روی BEP20 به آدرس تنظیم‌شده؛ این پرداخت مستقیماً درآمد/پرداخت سفارش است و هرگز به Balance کاربر اضافه نمی‌شود
- تولید کد سفارش یکتا مثل `SUB-AB12CD34`
- دریافت TXID و بررسی خودکار انتقال روی BSC: توکن، گیرنده، مبلغ و موفق بودن تراکنش بررسی می‌شود
- جلوگیری از استفاده دوباره از TXID
- بعد از تایید پرداخت، سفارش به مدیر اطلاع داده می‌شود تا تایید نهایی و سپس کمپین/تسک ساخته شود
- مدیر می‌تواند تسک بسازد و ربات به کاربران فعال اطلاع‌رسانی کند
- هر تسک برای هر کاربر فقط یک بار تا زمان رد شدن قابل ثبت است
- برای هر انجام تسک دقیقاً 2 اسکرین‌شات اجباری است
- مدیر دو مدرک را دریافت و تایید/رد می‌کند
- پاداش بعد از تایید به موجودی کاربر اضافه می‌شود
- مدیریت کاربران: block/unblock و تغییر موجودی
- برداشت حداقل 2 USDT روی BEP20؛ فقط از Balance قابل برداشت کاربر انجام می‌شود و کاملاً از پرداخت خرید سابسکرایبر جداست
- مدیر پرداخت برداشت را با TXID و اسکرین‌شات رسید ثبت می‌کند؛ در صورت رد، موجودی به کاربر برمی‌گردد

## متغیرهای Railway
حداقل این دو مورد را در Railway Variables قرار بده:
- `BOT_TOKEN`
- `ADMIN_ID`

آدرس پرداخت موردنظر از قبل در `config.py` و `.env.example` قرار داده شده:
`0xBE280149a80b1c7300d7Cd3a2F813f6aFD0845aB`

توکن پیش‌فرض بررسی USDT BEP20:
`0x55d398326f99059fF775485246999027B3197955`

## مهم درباره دیتابیس Railway
اگر می‌خواهی کاربران بعد از redeploy هم باقی بمانند، برای سرویس Railway یک Volume بساز و `DB_NAME=/data/taskly.sqlite3` بگذار. بدون Volume، SQLite روی فایل‌سیستم موقت سرویس ممکن است با redeploy از بین برود.

## اجرای محلی
```bash
pip install -r requirements.txt
cp .env.example .env
python main.py
```

### نکته امنیتی
هیچ private key یا seed phrase در این پروژه قرار داده نشده است. ربات فقط انتقال ورودی USDT را با RPC عمومی BSC می‌خواند و برای برداشت، ارسال واقعی وجه توسط مدیر انجام می‌شود.

## تفکیک مالی خرید و برداشت

- کیف پول پرداخت سیستم فقط برای **خرید سابسکرایبر/کمپین** استفاده می‌شود: `0xBE280149a80b1c7300d7Cd3a2F813f6aFD0845aB`
- اگر کاربر مثلاً **$100** سابسکرایبر بخرد، همان **$100 USDT** به این کیف پول پرداخت می‌شود و به موجودی قابل برداشت کاربر اضافه نمی‌شود.
- `0x...` که کاربر هنگام خرید می‌فرستد، **TXID تراکنش پرداخت خرید** است و برای تأیید همان سفارش استفاده می‌شود.
- برداشت کاملاً جداست: کاربر کیف پول BEP20 خودش را برای برداشت می‌دهد؛ مدیر از موجودی کاربر پرداخت می‌کند و TXID و رسید برداشت جداگانه ثبت می‌شود.
- مثال: با قیمت $0.02 برای هر سابسکرایبر، سفارش $100 یعنی 5,000 سابسکرایبر.
